# Business promo page

A one-page, responsive promotional site built with plain HTML5, CSS3 (Flexbox +
Grid) and vanilla JavaScript. No frameworks, no build step, no dependencies —
open `index.html` in any browser and it works, including straight off a USB stick.

---

## 1. File structure

```
.
├── index.html          The whole page. All visible text lives here.
├── css/
│   ├── base.css        Design tokens (colours, fonts, spacing) + reset + typography
│   ├── layout.css      Structure: header, nav, hero, section rhythm, grids, footer
│   └── components.css  Reusable pieces: buttons, cards, form, alerts, animations
├── js/
│   └── main.js         Nav, scroll animations, form validation, spam traps, feedback
├── assets/
│   ├── logo.svg        Header + footer logo mark
│   ├── favicon.svg     Browser-tab icon
│   └── hero.svg        Hero illustration
├── qa/                 The test scripts used to verify the page (optional, see §8)
└── README.md           This file
```

The three stylesheets are loaded separately and in this order: `base` → `layout`
→ `components`. Keeping them apart means a new section (Services, testimonials,
a pricing table) is added by appending to one file rather than hunting through
one long stylesheet.

## 2. Changing the colours

**Every colour on the page comes from one block: the `:root` section at the top
of `css/base.css`.** Change a value there and it updates everywhere — buttons,
links, headings, the contact panel, the icon chips, the focus rings.

```css
:root {
  --brand-900: #0d2340;   /* deepest navy — contact panel, footer   */
  --brand-800: #123255;   /* navy — headings                        */
  --brand-700: #1b466f;   /* mid navy — hovers                      */
  --accent:    #2f7fd1;   /* primary action colour (buttons, links) */
  --accent-dark: #2467ab; /* accent on hover                        */
  --accent-soft: #e8f1fb; /* light wash behind icons                */
  --gold:      #c8a349;   /* sparing highlight                      */
}
```

In practice you only need to touch two of them:

- `--brand-900` / `--brand-800` — your dark corporate colour.
- `--accent` — the single colour that says "click me".

Set `--accent-dark` roughly 10–15% darker than `--accent`, and `--accent-soft`
as a very pale tint of it. Keep dark text on light backgrounds and vice versa so
the page stays readable for everyone.

The logo files (`assets/logo.svg`, `assets/favicon.svg`) and the hero
illustration carry the same hex values inside them — they are plain text, so you
can open them in any editor and find-and-replace the colours to match.

## 3. Changing the fonts

The page ships with a **system font stack**: it renders in the native interface
font of whatever device the visitor is on, loads instantly, and needs no
internet connection. It is set once, in `css/base.css`:

```css
--font-body: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...;
--font-head: var(--font-body);          /* headings use the same family */
```

To use a webfont instead — say Inter for the body and Poppins for headings:

1. Add the font link inside `<head>` in `index.html`, above the stylesheets:

   ```html
   <link rel="preconnect" href="https://fonts.googleapis.com">
   <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
   <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&family=Poppins:wght@600;700&display=swap" rel="stylesheet">
   ```

2. Point the tokens at them in `css/base.css`:

   ```css
   --font-body: "Inter", -apple-system, "Segoe UI", Roboto, sans-serif;
   --font-head: "Poppins", "Inter", -apple-system, sans-serif;
   ```

Always keep the fallbacks after your font name — that is what visitors see for
the split second before the webfont arrives, and what they see permanently if it
fails to load.

**Text sizes** are also tokens, in the same block (`--fs-h1`, `--fs-base`, …).
They use `clamp()`, which scales the type smoothly between phone and desktop —
`clamp(minimum, preferred, maximum)`. To make headlines larger everywhere, raise
the third value of `--fs-h1`.

## 4. Changing the text

All copy is in `index.html`, in plain paragraphs. Nothing is generated by
JavaScript, so what you see in the file is what appears on the page.

| What | Where in `index.html` |
|---|---|
| Browser tab title, meta description | `<head>`, top of the file |
| Business name in the header + footer | the two `.brand` blocks |
| Headline and intro sentence | `.hero__content` |
| The 200–300 word About Us copy | the block marked `About Us copy` |
| The four figures (11 yrs, 180+, …) | `.stats` section |
| The three "Why clients stay" cards | `.card-grid` |
| Email, phone, address | `.contact__list` |
| Form labels and placeholders | the `<form>` block |
| Footer address and company number | `.site-footer` |

The About Us block is one plain group of `<p>` paragraphs. Add or remove
paragraphs freely — on wide screens they flow into two balanced columns
automatically, and on phones they stack into one. No CSS changes needed.

The copyright year in the footer is set automatically each January by
`js/main.js`, so it never goes stale.

**Swapping the hero image for a photograph:** drop your file into `assets/` and
change one line in `index.html`:

```html
<img class="hero__image" src="assets/your-photo.jpg"
     alt="Short description of what the photo shows" width="1440" height="1080">
```

Keep the `width`/`height` roughly equal to the real pixel size of the image —
that is what stops the page from jumping around while the photo loads. A
landscape image around 4:3 or 3:2 suits the layout best.

## 5. The contact form

Out of the box the form is in **demo mode**: it validates properly, runs its
spam checks, and shows the confirmation message, but nothing is sent anywhere.
That is deliberate — it means the page can be opened straight from your hard
drive and demonstrated end to end with no server involved.

### Validation

Checked in the browser as the visitor types, and again on submit:

- **Name** — required, at least 2 characters
- **Email** — required, must be a properly formed address
- **Message** — required, at least 20 characters, 2000 maximum (live counter)
- **Consent** — the checkbox must be ticked

Errors appear under the offending field in red, the field is outlined, and focus
jumps to the first problem. Errors clear as soon as the visitor starts fixing
them. Everything is announced to screen readers via `role="alert"`.

### Spam prevention

Two traps, both invisible to real visitors and requiring no third-party service,
no API key and no cookie banner:

1. **Honeypot** — a `Company website` field hidden off-screen. People never see
   it; bots fill in everything they find. If it arrives filled, the submission
   is silently discarded. The bot is shown a normal success message, because
   telling a bot it failed only teaches it to try again.
2. **Timing trap** — anything submitted less than 3 seconds after the page
   loaded is treated as automated and dropped the same way.

If you later want reCAPTCHA as well, add Google's script tag and their widget
`<div>` above the submit button; the existing validation will keep working
alongside it.

### Connecting a real endpoint

Open `js/main.js` and edit the `CONFIG` block at the very top:

```js
var CONFIG = {
  endpoint: 'https://formspree.io/f/yourid',  // or leave null to use the form's action=""
  demoMode: false,                            // false = actually send it
  sendAsJson: false,                          // true if your API expects JSON
  ...
};
```

Then update the placeholder in `index.html` if you prefer to keep the address
there instead:

```html
<form ... action="https://example.com/your-form-endpoint" method="post">
```

With `demoMode: false` the form POSTs the fields (`name`, `email`, `message`,
`consent`) to that address. A successful response shows the green confirmation;
a network failure or an error status shows the red "that did not send" message
with your fallback email address. The honeypot and timestamp fields are stripped
before sending.

The wording of both messages is in the same `CONFIG` block, under `messages`.

Anything that accepts a POST will work: Formspree, Basin, FormSubmit, Netlify
Forms, a PHP script on your own hosting, or a custom API.

## 6. Adding a Services section later

The card grid is already built for it, so it is a copy-paste job:

1. In `index.html`, duplicate the `<section id="values">` block, change the id to
   `services` and rewrite the headings and cards.
2. Uncomment the nav link that is already sitting in the header:
   `<li><a class="nav__link" href="#services">Services</a></li>`
3. If you want it on a tinted background, add `section--alt` to the section's
   class list — that rule already exists in `layout.css`.

The grid uses `auto-fit`, so three, four or five cards all lay out correctly
with no further CSS.

## 7. Responsive and accessibility notes

- Laid out mobile-first and verified at **320, 375, 768, 1024, 1280 and 1600px**
  with no horizontal scrolling at any width.
- Navigation collapses to a burger menu below 880px; it closes on Escape, on
  choosing a link, and resets itself if the window is widened while open.
- Type and spacing scale fluidly with `clamp()`, so there are no awkward jumps
  between breakpoints.
- Full keyboard support, a visible focus ring on every control, a "skip to
  content" link, labelled form fields and landmark elements throughout.
- Animations are disabled automatically for anyone whose system is set to
  "reduce motion".
- With JavaScript switched off the page still renders completely — the reveal
  animations are scoped to a class that only exists when JS is available, so
  nothing can be left invisible.

Everything below was run against these exact files.

| Check | Result |
|---|---|
| W3C HTML validator (validator.w3.org/nu) | **0 errors, 0 warnings** |
| W3C CSS validator (jigsaw.w3.org), all 3 files | **0 errors** |
| Layout, 320 → 1600px | no horizontal overflow at any width |
| Contact form behaviour, 26 assertions | all pass |
| Chromium (Chrome + Edge), Firefox, WebKit (Safari) | identical behaviour, no console errors |

The scripts that produce those results are in `qa/` and need Python with
Playwright installed. They are included for transparency; the page itself has no
dependency on them and the folder can be deleted.

```
python3 qa/shots.py      # responsive layout + screenshots
python3 qa/form.py       # form validation, spam traps, navigation
python3 qa/browsers.py   # the same checks in Chromium, Firefox and WebKit
```

## 9. Publishing it

There is no build step. Upload the contents of this folder to any web host —
shared hosting, GitHub Pages, Netlify, Cloudflare Pages, an S3 bucket — keeping
the folder structure intact. `index.html` must sit at the top level.
